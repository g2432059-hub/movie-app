# 失敗例の分析(dev・画面の確認から。testの結果は使っていない)

## 失敗例1: SFの入力でSFが出ない
- 入力: Star Wars IV/V/VI=5、Matrix=4、Terminator 2=4、λ=0
- 結果: 上位10件にSci-Fiが0本(Shawshank、Raiders、Usual Suspects など)。fold-inの l2=1.0 に変更後も、check_model の上位5件にSci-Fiはない(入力済みのStar Wars IVを除く)
- 原因の段階: モデル。NCFはジャンルを入力に使わず、評価のパターンだけから学ぶ。入力5本のfold-inでは、個人の好みより、評価の高い人気作の傾向が強く出ると考えられる(推測)
- 根拠: dev全体で人気順(P@10 0.296)がNCF(0.178)を上回る
- 未検証: SF映画の予測が、どの順位にあるか

## 失敗例2: 高評価ばかりの入力で、予測が5.00に頭打ち
- 入力: アニメ5本(評価5,5,5,5,4)、λ=0.25
- 結果(修正前): 上位10件のうち9件が5.00。生の予測は、5.0以上が67本、最大5.54
- 原因の段階: モデル(fold-in)と後処理。fold-inが高評価ばかりの入力で予測を高く寄せ、clipで頭打ちになった。さらに、後処理がclip後の値で順位づけしており、同点が映画ID順に並んだ(実際の不具合)
- 対応: (1)順位づけをclip前の値に変更。(2)fold-inの l2 を0.01→1.0に変更(devで決定)。同じ入力で、5.00は2件に減った
- 残る課題: 上位2件は5.00のまま。l2の最適値が、実験した範囲(〜1.0)の端にある

## 失敗例3: 入力が低評価寄りの利用者で、NCFのRMSEが伸びない
- 条件: 入力5本のうち4点以上が0〜1本の利用者(dev 74人)
- 結果(RMSE): 平均評価 1.101、MF 1.040、NCF 1.090。高評価寄り(4〜5本)では、平均評価 0.930、MF 0.878、NCF 0.886
- 事実: 平均評価でも低評価寄りは悪い(予測が難しい利用者)。ただし、NCFのMFとの差は、低評価寄りが最大(+0.050。高評価寄りは+0.008)で、平均評価に対する改善もほぼない
- 原因の段階: モデル(NCFの構造とfold-in)。仮説: MFは利用者のバイアス(評価の甘さ辛さ)を持つが、NCFは持たない(予測=全体平均+MLP)ため、辛い利用者の水準を表せない。未検証
- 注意: 74人で、検定はしていない。l2を変えても、低評価寄りの差は残った(l2=0.01〜1.0で1.171〜1.090)
- 今後の候補: NCFに利用者バイアスを加える(再学習が必要)

## 失敗ではない限界(評価の設計に由来)
- 評価件数が少ない利用者ほど、P@10が低い(NCF: 20件以下0.051、200件超0.337)。人気順でも同じ傾向(0.098→0.535)で、手法によらない。評価していない映画は不正解になるため
- top25の基準は、同点を含むため、評価が1つの値に集中している利用者では、全件が高評価になる(高評価の割合は、平均0.48)
- 入力の評価がすべて同じ利用者(18人)は、むしろ精度が高かった(P@10 0.233、RMSE 0.852)。fold-inが退化する想定は、この結果では確認されなかった(人数が少ない)
