## 1. 目的と概要

| 項目 | 内容 |
|---|---|
| 一言で | 見た映画3本以上と評価(1〜5)を入力すると、ジャンルが偏りすぎないおすすめ10本が予測評価つきで表示される |
| 利用者・場面 | 見る映画に迷う学生が、週末に見る作品を選ぶとき |
| 確かめること | ジャンルの多様性の重み λ を変えたとき、おすすめの当たりやすさ(Precision@10)とジャンルの種類数がどう変わるか |
| 深層学習の部分 | Neural Collaborative Filtering(NCF)による評価予測と、入力評価から利用者ベクトルを求める fold-in |
| ルールの部分 | 入力検証、映画名→番号の変換、見た映画の除外、ジャンル多様性の再ランキング、上位10件の抽出 |

## 2. 範囲

**MVP（最低限）**
1. 数本の映画と評価を入力できる。
2. 学習済みモデルで評価を予測できる。
3. おすすめ10本の映画名・予測評価・ジャンルを表示できる。

**範囲外**：公開前の映画の予測、あらすじ・監督・出演者の利用、MovieLens 10Mへの拡張、login、Internetへの公開。

## 3. 画面設計（`app.py`）

| 要素 | 仕様 |
|---|---|
| 映画の選択 | 検索つきの選択欄(データセット内の映画のみ)。自由入力は受け付けない |
| 評価の入力 | 1〜5の整数 |
| 多様性の重み λ | スライダ(0〜1、初期値0.25) |
| 実行 | 3本以上で「おすすめを表示」を有効にする |
| 出力 | 表：順位・映画名・予測評価・ジャンル |
| エラー | `st.error` で理由を表示し、推薦しない |

**エラー条件**：3本未満／同じ映画の重複／データにない映画／評価が1〜5の整数でない。

**画面の方針**：`app.py` は `recommender.py` の関数を呼ぶだけにする。モデルの読込は `@st.cache_resource` で1回にする(Streamlitは操作のたびに再実行されるため)。

## 4. 処理の流れ

```text
入力 → 前処理 → [NCF + fold-in] → 後処理 → 表示
```

| 段階 | 処理 | DL/ルール | 関数 |
|---|---|---|---|
| 入力 | 映画と評価を受け取り、検証する | ルール | `validate_inputs()` |
| 前処理 | 映画名 → movieId → モデル用の連番index | ルール | `to_movie_index()` |
| モデル | 利用者ベクトルをfold-inで求め、全映画の評価を予測 | **DL** | `fold_in_user()`、`predict_ratings()` |
| 後処理 | 見た映画の除外、再ランキング(λ)、上位10件 | ルール | `rerank()` |
| 表示 | 映画名・予測評価・ジャンルを表にする | ルール | `app.py` |

全体を呼ぶ関数：`recommend(items, lam=0.25) -> [(title, score, genres), ...]`

## 5. モジュール構成

| file | 役割 | 主な関数・引数 |
|---|---|---|
| `make_split.py` | 利用者単位でtrain/dev/testに分け、dev/testは入力5本と評価用に分ける | seed=42 |
| `train.py` | train利用者の評価で平均評価・行列分解・NCFを学習し、重みを保存 | `--dim`(仮32) |
| `data_utils.py` | MovieLensの読込、映画/利用者のID対応表の作成 | `load_ratings()`、`load_movies()`、`build_id_maps()` |
| `models.py` | MF・NCFのモデル定義(train.pyとrecommender.pyで共有) | |
| `metrics.py` | RMSE、高評価の閾値、Precision@10、ジャンル数。`tests/test_metrics.py` で手計算の例を検証 | |
| `recommender.py` | 推論(検証、変換、fold-in、予測、再ランキング)。画面に依存しない | 上表の関数、`load_model()` |
| `app.py` | Streamlit画面 | |
| `evaluate.py` | 分割を引数で受け取り、指標を計算する | `python evaluate.py splits/dev --model ncf --lam 0.25` |
| `check_model.py` | モデルへ渡す直前の値と生の出力を表示する(確認用) | |

## 6. データ設計

- データ：MovieLens 1M(GroupLens)。約6,040人、約3,700本の映画、約100万件の評価【件数は要確認】
- 形式：`ratings.dat`・`movies.dat`は区切りが `::`。ジャンルは `|` 区切り。文字コードに注意【要確認】
- 取得：公式ページからダウンロードし、READMEに手順を書く。**再配布しない。** 出典を明記する

**分割**（乱数seed=42、利用者単位）

| 区分 | 割合 | 使い方 |
|---|---|---|
| train | 80% | モデルの学習のみ |
| dev | 10% | 調整・early stopping・λの尺度確認。何度でも使える |
| test | 10% | 最終確認。評価は**2回だけ** |

- dev/testの各利用者は、評価から**5本を入力用**にランダムに選び(seed固定)、残りを評価用にする。
- 分割scriptで、3集合の利用者の共通部分が空であることを `assert` で確認する。
- early stopping用に、train利用者の評価からランダムに5%を検証用(val)として取り分ける(学習には使わない)。devユーザーのfold-inを毎epoch行う手間を避けるため。
- 映画の埋め込みはtrain利用者の評価だけで学習する。**訓練に無い映画**は、全手法で評価から除外し、件数を報告する。

## 7. モデル設計

### 7.1 NCF（提案手法）

```text
利用者ベクトル u (32) ┐
                      ├→ 連結(64) → [64] → [32] → [16] → [1] → 予測評価
映画ベクトル  m (32) ┘              ReLU   ReLU   ReLU  線形
```

| 項目 | 設定（仮） |
|---|---|
| 埋め込み次元 | 32(16/32/64のうち、devで1〜2通り) |
| 中間層 | 64 → 32 → 16、ReLU。Dropout 0.1〜0.2は任意 |
| 出力層 | 1ユニット、活性化関数なし。出力 = 全体平均 + 補正。推論時に1〜5へclip |
| 損失・最適化 | MSE、Adam、学習率1e-3(仮) |
| 停止 | early stopping(train利用者の評価の5%を検証用valとして取り分け、そのRMSEが数epoch悪化したら停止。devは使わない) |
| 正則化 | 重み減衰(L2、1e-5程度から) |
| 学習データ | **全評価**を使う(高評価だけで学習しない) |

### 7.2 fold-in（新しい利用者の扱い）
- 映画埋め込みと中間層を**固定**し、利用者ベクトルだけを入力5本(画面では3本以上)の評価に合うよう最適化する。
- 初期値：train利用者のベクトルの平均。L2で平均から離れすぎないようにする。step数50、lr 0.05は仮置き。
- 5本に対して32個の数値を動かすため過学習しやすい。強さはdevで確認する。
- 既定値を1.0に変更した（理由は `docs/IMPROVEMENT_PLAN.md`）。

### 7.3 比較対象
| 手法 | 内容 |
|---|---|
| 平均評価 | trainでの映画ごとの平均。評価数が少ない映画の補正(kはdevで決定)。**入力の5本を使わない** |
| 行列分解 | 同じ埋め込み次元。予測 = 内積 + 偏り項。**同じfold-inで評価** |
| 人気順（任意） | train評価数の多い順 |
| 無作為 | 下限の確認 |

> NCFは入力の評価を使うが平均評価は使わない。NCFが平均評価に勝っても、「モデルの効果」と「利用者情報を使った効果」を区別できない。区別したい場合は、入力5本の平均を足した比較対象を追加する(任意)。

## 8. 後処理（再ランキング）

候補：入力以外の全映画(訓練に無い映画を除く)。予測評価を1〜5にclipしたものを `pred(i)` とする。

```text
selected = []
for 1..10:
    for each candidate i:
        novelty(i) = (iのジャンルのうち、selected全体のジャンルに含まれないものの数) / (iのジャンル数)
        score(i)   = pred(i) + λ * novelty(i)
    選択 = argmax score(i)   # 同点は映画ID昇順
    selected に追加
```

- λ=0 のとき、予測評価順と一致する(確認事項)。
- 表示する予測評価は `pred(i)`(λの加点は含めない)。
- 予測評価は1〜5、noveltyは0〜1なので、**λの尺度はdevで確認する**(λ=1でも順位がほとんど変わらない場合は水準を見直す)。

## 9. 評価設計

**確かめること**：λを変えたとき、Precision@10とジャンル数がどう変わるか。

| 指標 | 定義 |
|---|---|
| RMSE | 評価用の評価に対する√(平均((予測−実際)²))。**pooled**(全評価をまとめる)を主、利用者ごと平均を副 |
| Precision@10（主） | 上位10件のうち、**利用者ごとの高評価**だった映画の割合。高評価＝その利用者の評価用データの75パーセンタイル以上(同点を含む)。利用者ごとに計算して平均 |
| Precision@10（副） | 高評価＝4点以上(固定)。主指標の結論が基準によらないかの確認 |
| ジャンル数 | 上位10件に含まれるジャンルの種類(重複なし) |

**決めたこと**

| 項目 | 決定 |
|---|---|
| 予測のclip | する(1〜5) |
| 入力の5本 | 評価対象から除く |
| 高評価の基準（主） | 利用者ごとの**評価用データの上位25%**。閾値 t = `numpy.percentile(評価用の評価, 75, method="lower")`、高評価 = 評価 ≥ t。評価は整数で同点が多く、割合は25%より大きくなりうる |
| 高評価の基準（副） | 4点以上(固定)。同じ関数に閾値の決め方を引数で渡して両方を出す |
| 評価が全部同じ値の利用者 | 主指標から除外し、人数を報告する |
| 高評価の割合の確認 | devで利用者ごとの高評価の割合(平均・中央値)と除外人数を記録する(基準の選び直しには使わない) |
| 候補集合 | 入力以外の全映画(訓練に無い映画を除く) |
| 同点の順位 | 映画ID昇順 |
| 評価用が少ない人 | 除外せず含める |
| 入力の本数 | 5本固定 |

**比較する条件**

| 条件 | 水準 | 変えないもの |
|---|---|---|
| λ | 0／0.1／0.25／0.5／1.0 | 学習済みモデル、入力5本、fold-inの設定、seed、候補集合、推薦件数 |

**補助的な分析（条件の比較ではない）**：入力5本のうち高評価が何本かで利用者を分けて結果を見る。

**dev/testの運用**
- 調整(次元、正則化、fold-in設定、λの既定値)は**devだけ**で行う。early stoppingはtrain内のvalで行う。
- 既定λの規則を**先に書く**(例：P@10がλ=0の○%以内で、ジャンル数が最大のλ)。○はdevの尺度確認の後に決め、commitしてから結果を見る。
- testの評価は10/28(改善前)と11/1(改善後)の**2回**。`evaluate.py` は実行前に確認し、`results/test_runs.log` に履歴を残す。

**限界（報告書に書く）**
- MovieLensには評価した映画の正解しかなく、Precision@10の絶対値は低く出る。手法間の相対比較として読む。
- 上位25%という基準と、既定λの規則の○%は恣意的である。上位25%は「その人にとって相対的に良い」を表し、「好んだ」とは意味が異なる。閾値の計算には評価用データの分布が必要で、アプリ実行時には使えない評価専用の定義である。主指標の絶対値は固定基準(4以上)と比べられない。
- 入力5本だけの情報で好みを推定するため、利用者ごとの精度は不安定になりうる。

## 10. 対象外・想定外の入力への対応

| 入力 | 期待する動作 |

## 12. リスクと代替案

| リスク | 代替案 |
|---|---|
| fold-inが10/25までに動かない | 入力映画の学習済み埋め込みの平均との類似度で順位を付ける |
| NCFが行列分解・平均評価に勝てない | そのまま報告し、差の理由を分析する(MLPが内積に劣る場合があることも既知【要確認】) |
| 候補集合の作り方で結果に偏りが出る | devで設計を確定し、限界として書く |
| 入力から出力まで動かない | 再ランキングを後回しにし、MVPを先に完成させる |
| 時間が足りない | 評価は最小構成(RMSE、P@10、ジャンル数、λの比較、dev/test分離、失敗例3件) |
